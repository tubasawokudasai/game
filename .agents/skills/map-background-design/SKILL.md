# 地图艺术设计与底图生成 Skill

## 一、核心设计原则

你不是一个只负责生成某种固定风格画卷的生成器，而是一名具备独立世界观感知能力的游戏世界地图艺术指导。

你的任务是根据当前地图的世界观和剧情，设计具有独特辨识度、空间逻辑和叙事能力的地图底图。

### 1. 独立世界观与多元美术风格

**每张地图都可以拥有完全独立的世界观，绝不存在统一的仙侠题材或风格限制。**

不同地图可以分别采用：
- 东方仙侠、武侠、玄幻（如工笔重彩、青绿山水、写意水墨、仙侠写实等）
- 西方奇幻、中世纪、魔法文明（如古典油画、哥特奇幻、中世纪插画风等）
- 现代都市、赛博朋克、科幻世界（如霓虹科幻、未来都市全景、高科技终端等）
- 末日废土、蒸汽朋克、机械文明（如柴油朋克、齿轮机械、黄沙废土等）
- 神话、历史架空、异星文明或其他原创题材

不得为了统一游戏风格而强行统一不同地图的建筑、服装、种族、文明、道具和美术风格。
根据场景所属的独立世界观，自主选择最相符的视觉语言、材质与色彩表达。

### 2. 不限制地图构图与视角

根据地图实际用途与空间结构自主选择构图，包括但不限于：

- 正俯视
- 斜俯视
- 高空鸟瞰 / 宏观全景
- 等距轴测（Isometric）
- 电影级广角
- 剖面式空间展示
- 多层立体空间结构

地图底图必须服务于实际游戏玩法与场景定位：
- 城镇、街区、建筑内部：需要让玩家清晰辨识道路、建筑、门户与交互区域，空间结构必须清晰合理。
- 世界宏观大地图：突出板块、山川、疆界与地标方位。
- 秘境、地宫、遗迹：突出深度、高低差与探索通道。

### 3. 地图必须具备叙事能力

每张地图生成前，先思考：

- 这个地方为什么存在？
- 谁建造了它？代表了何种文明与势力？
- 这里发生过什么？有无战争、灾变或繁荣留下的痕迹？
- 当前处于什么状态？
- 有哪些能够体现历史与生活痕迹的环境细节？
- 玩家进入时，应当感受到怎样的氛围？

环境叙事应通过建筑风貌、地貌特征、残骸、植被、光影、文明遗迹等自然呈现，禁止无意义的元素简单堆砌。

## 二、地图类型与创作策略

根据地图实际用途分类设计：

### 1. 世界地图与宏观板块
重点表现大陆、海洋、山脉、空岛、星区等宏观空间关系，标定不同文明与势力的地理分布，道路交通网络与天然阻隔。

### 2. 城镇、都城与街区
重点表现城墙、门户、主要干道、广场、商贸区、居住区、功能设施，体现城市的文明高度、社会秩序与市井生活痕迹。

### 3. 势力据点、宗门与设施
重点表现核心建筑群与环境的依附关系（如悬崖要塞、依山宗门、浮空研究所、地下掩体等），体现该势力的技术、信仰与历史底蕴。

### 4. 建筑内部与地下空间
重点表现室内开间、功能分区、陈设布局、光影明暗，或地宫、矿坑、溶洞的层次与危险机关。

### 5. 野外区域、秘境与废墟
重点表现自然地貌、古老遗迹、生态特征、高低落差与隐藏路径。

### 6. 战场、科幻设施与特殊空间
重点表现掩体、残骸、高低差、机械结构、危险能量场或超现实时空氛围。

## 三、生成前的自主设计流程

每次生成地图之前，先根据当前地图独立世界观制定设计方案：

1. 地图名称、世界观背景与场景类型
2. 地理环境与空间尺度
3. 建筑风格与关键视觉地标
4. 核心视觉主题与美术风格
5. 主色调、天气与光照
6. 环境叙事细节
7. 视角与构图选择

不同世界观和地域的场景应有明显的视觉差异，不强行统一成一种画风。

## 四、Google Stitch 生成规范

使用 Stitch MCP 的 `generate_screen_from_text` 工具。

默认项目 ID：
`11287778428665999906`

deviceType：
`AGNOSTIC`

提示词必须根据当前场景单独创作，包含：
- 场景地理、建筑布局与空间构图
- 关键视觉地标与叙事细节
- 符合当前地图世界观的美术风格与材质表现
- 视角（如正俯视、斜俯视、等距轴测等）
- 色彩、光影与环境氛围

### 游戏底图通用约束

- 不出现游戏 UI、按钮、HUD、血条
- 不出现地图定位图标、文字标签和水印
- 不出现与游戏角色立绘重复的独立人物特写
- 保持场景底图环境完整

## 五、地图资产处理（调用自动化脚本）

项目提供自动化下载与转码脚本：

`.agents/skills/map-background-design/scripts/download_map_bg.py`（或根目录 `scripts/download_map_bg.py`）

**Agent 必须直接调用该脚本，严禁自行编写重复的下载转码脚本；现成脚本失败时报告错误，不得自行重写。**

### 运行环境与解释器说明

- 脚本完全基于 Python 3 标准库与 macOS 原生 `sips` 工具，**不需要第三方 PIL / Pillow**。
- 推荐解释器路径：系统默认 `/usr/bin/python3`（或 `python3`）。若其他流程需要 Pillow，可使用 `/Users/wjb/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3` 或运行 `pip3 install pillow`。

### 使用方法

确保已设置环境变量：
```bash
export STITCH_API_KEY="your_stitch_api_key"
```

执行下载与转码：
```bash
python3 .agents/skills/map-background-design/scripts/download_map_bg.py \
  --url "<downloadUrl>" \
  --key "<scene_key>"
```

脚本会自动：
1. 校验 `STITCH_API_KEY` 与下载响应状态码。
2. 解码并使用 macOS `sips` 转换为 PNG 格式。
3. 保存至项目资源目录：`frontend/public/assets/maps/{scene_key}_bg.png`。
4. **严格校验文件存在且大于 0 字节**（防止下载静默失败）。
5. 地图底图保留完整环境画面，**无需做去背景处理**。

## 六、场景 API 配置

在创建或更新场景时，将实际资源路径配置到 `background_url`：

```text
/assets/maps/{scene_key}_bg.png
```

必须使用真实生成并保存的资源路径。严禁在没有真实产出图片时假装配置成功。

## 七、质量验收

1. 地图底图是否完全符合当前地图的世界观和空间用途设定？
2. 道路、建筑入口与交互空间是否清晰合理，空间结构是否严密？
3. 是否具备鲜明的视觉辨识度与环境叙事细节？
4. 是否避免了画风强行统一，与不同世界观的其他地图保持合理的风格差异？
5. 资源文件是否真实保存至 `frontend/public/assets/maps/` 且能正常加载？
